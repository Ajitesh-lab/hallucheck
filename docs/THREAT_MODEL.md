# Threat model

HALLUCHECK reads repositories and can execute explicitly configured checks. Repository files, agent events, tool text, model outputs, package scripts, and hook stdin are untrusted observations. The local configuration, installed verifier binaries, TypeScript runtime, OS account, and explicit human terminal are trust anchors.

| Threat                          | Control                                                                                                                                                | Boundary / residual risk                                                                                                                                                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source/secret exfiltration      | No inference without opt-in; compact claims and evidence summaries only; mandatory secret redaction and outbound environment-value stripping; size cap | Redaction cannot recognize every proprietary secret. Explicit claims and diagnostics can themselves contain sensitive data. Review opt-in carefully.                                                                                                                                  |
| Repository prompt injection     | Repo/claim text is data, typed Jev questions have fixed instructions, outputs are schema-validated labels/numbers only                                 | A model can still be influenced by adversarial data; it cannot execute commands, approve, verify facts, or override contradictions.                                                                                                                                                   |
| Traversal and escaping symlinks | Canonical root containment and realpath checks, fixed compiler library exception, exclusion globs                                                      | A hostile process swapping paths concurrently can exploit check/read races. This is a same-account development tool, not an OS sandbox.                                                                                                                                               |
| Agent command execution         | Never evaluate toolInput or model strings; fixed argv owner allowlist; shell disabled                                                                  | Tests and package scripts execute repository code. Owner must trust them. PATH executables and repo config are trust anchors.                                                                                                                                                         |
| Resource exhaustion             | Context/file/directory caps, bounded queues/LRUs, timeouts, concurrency limits, process-group kill, output caps                                        | Compiler work is synchronous; a pathological TypeScript file can still consume CPU/memory until the pass returns.                                                                                                                                                                     |
| Forged test success             | Host logs audited as untrusted; only independently executed checks establish test pass; snapshot and skip contract checked                             | Actual test coverage and runner honesty depend on owner configuration. Excluded artifacts and environment changes are not a source snapshot guarantee.                                                                                                                                |
| Forged model confidence         | Typed response checks; model metadata retained; policy cannot convert probabilities into verification                                                  | Thresholds are provisional and uncalibrated.                                                                                                                                                                                                                                          |
| Forged human approval           | No approval tools over MCP/socket/hooks; separate interactive TTY; refuse common agent/CI environments; state-specific append-only application records | OS processes with the same UID and arbitrary filesystem/PTY access can impersonate a terminal or edit SQLite. Strong human identity requires an external authenticated service or hardware presence mechanism, neither included. Reviews are advisory and never unlock tool policies. |
| Local socket abuse              | Repository-bound protocol, private state dir and 0600 socket, limited clients/frames, no review operation                                              | Same UID processes can submit events and read findings. No peer attestation.                                                                                                                                                                                                          |
| Stored-secret disclosure        | Sanitized findings/audits/output; private state dir and database; fixed SQL parameters                                                                 | No encryption at rest; SQLite is not a tamper-evident ledger. Protect the OS account and backups.                                                                                                                                                                                     |
| Malicious lifecycle files       | Host trust flow and manual install; no automatic host trust                                                                                            | Protect installed plugin/CLI files and review changes. Hook failures cannot be relied upon as universal fail-closed policy.                                                                                                                                                           |

A review is attached to an exact finding and source snapshot, never a global detection disable. The engine never modifies source files or applies generated repair instructions.

Privacy excludes `.env*`, key files, and configured sensitive paths from default context. The TypeScript host may read type definitions locally but does not send their contents. Output sanitization strips terminal control characters and common credential patterns; outbound requests also remove nontrivial current process environment values. Context is capped before any HTTP call. Jev redirects are rejected so credentials cannot follow a redirect to another origin.

The daemon must be restarted to apply owner configuration changes. Do not use this MVP as the sole approval or destructive-command firewall; use the host sandbox and approval policies. The conservative destructive-command guard is deliberately separate from hallucination reasoning and is not a complete shell parser.
