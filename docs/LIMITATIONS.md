# Known limitations

- This is an evidence-grounded MVP, not a proof of whole-project correctness. VERIFIED always applies to the exact scoped assertion and repository snapshot.
- Free text is retained as a single limited-quality claim. Jev provides classification/routing, not unconstrained claim generation. Broad completion, migration compatibility, and business requirements need explicit evidence or human acceptance criteria.
- Initial semantic analysis covers TypeScript/JavaScript only. Scans cover at most 64 selected source roots / 128 assertions; no full-project correctness certificate is emitted.
- The compiler honors local tsconfig options through a safe reader but disables compiler plugins. It checks selected source roots and reachable imports, not every tsconfig project reference. External workspace symlinks are denied, including dependencies linked outside the canonical repository.
- Source snapshots exclude dependencies, generated output, secrets, and configured paths. Relevant compiler dependency lookups have separate cache invalidation. Test freshness does not attest to arbitrary environment variables, installed runtime dependency contents, databases, remote services, native binaries, or files beyond the bounded snapshot. Files modified maliciously between filesystem checks remain a race.
- Warm source hashing uses inode/size/mtime/ctime identities to avoid rereading unchanged content. This is not a tamper-proof filesystem monitor.
- Hook tool records are audited but cannot establish independently trusted test execution. Use owner-configured exact check commands for test evidence. Unknown skip status is UNSUPPORTED. No arbitrary shell-output success parser exists.
- No external official-documentation search/retrieval implementation. A future typed retrieval interface is provided. Dependency checks establish local declarations and type resolution, not registry availability or general semver compatibility.
- The mandatory destructive-action guard handles obvious known destructive argv tokens; aliases, custom scripts, shell metaprogramming, and arbitrary programs can escape it. Normal host approval/sandbox policies remain required. Human review records do not bypass the guard.
- The interactive human queue cannot establish strong identity against a hostile process with the same UID. It refuses MCP, daemon, non-TTY, CI, and common agent environments, but no independent identity provider is included. Audit rows are application-append-only, not tamper-evident storage.
- PostToolUse runs asynchronously through host scheduling. Other synchronous host events avoid Jev for routine pre-tool checks. The daemon queue supports cancellation of superseded jobs, but an in-progress synchronous compiler pass cannot be interrupted. The `asyncVerification` setting is reserved for embedding preference; shipped async hook scheduling is configured in hook manifests and remains asynchronous regardless of that setting.
- Configuration is loaded when the daemon starts. Restart to apply changes. Persistent state is per canonical repository, with no multi-tenant or network listener.
- Unix domain socket paths must be <=100 bytes. Long repository paths need a shorter checkout path. Windows is unsupported.
- Jev request cache uses requested model plus a short 60-second TTL. Actual model_version is retained in every finding. A provider changing a model alias within that TTL can temporarily reuse the previous build's prediction; independent evidence status is unaffected.
- No live Jev request or latency measurement was performed without explicit credentials and opt-in. Unit HTTP mocks are not live model results. The small, synthetic labelled corpus is a regression suite, not a representative estimate of production detection accuracy.
- Performance measurements are warm in-process fixture measurements. CLI startup, large monorepos, cold compilation, network inference, and remote host execution have different overhead. No production SLO is implied.
- Claude and Codex lifecycle contracts differ. Codex `ask` is unsupported; mandatory guards map to deny. Codex hook trust is an explicit user step. Lifecycle-hook plugins are manual installs and cannot enter the public directory.
- Tested on macOS with Node 25.8.1, Codex CLI 0.154.0, and Claude Code 2.1.273. Node 22.13.1 additionally passed an actual fixture scan. Linux needs CI validation before a broader release.

Native interaction limitations and exact action triggers are documented in [NATIVE_INTERACTION.md](NATIVE_INTERACTION.md). No native notification/button, arbitrary idle-turn resume, or strong same-UID human identity capability is claimed. Native risk acknowledgment does not invoke the legacy security-review CLI.
